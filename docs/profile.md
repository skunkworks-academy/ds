# Capability Profile

This public capability profile is intentionally sanitised. It represents the professional baseline needed to structure the IDR without publishing private contact, financial or detailed assessment information.

## Established strengths

- 15+ years of enterprise infrastructure, endpoint and systems-administration experience
- Microsoft 365, Azure, Intune, SCCM/MDT, Active Directory and Exchange
- Windows endpoint modernisation, deployment and support strategy
- Microsoft Defender and Sentinel exposure
- networking, firewalls, VPNs, DNS, DHCP, routing and switching
- virtualisation, backup, disaster recovery and infrastructure maintenance
- incident, problem, change and service-management practices
- technical troubleshooting and senior escalation handling
- project coordination, migrations and proof-of-concept delivery
- architecture planning, governance/compliance exposure and enterprise modernisation work
- stakeholder communication, vendor collaboration and mentoring

## Existing foundation credentials and training

The source material represented in this IDR includes foundation training/credentials such as:

- A+ certification;
- N+ certification;
- software specialist training;
- web design and Microsoft Office training;
- Advanced Excel, Microsoft Word and introductory programming exposure.

These are treated as baseline history. The current IDR focuses on senior architecture, security, automation and leadership evidence.

## Development leverage

The roadmap deliberately reuses existing strengths:

- Microsoft endpoint and infrastructure experience becomes the starting point for Zero Trust/endpoint architecture;
- Defender/Sentinel exposure becomes the foundation for SOC/detection engineering;
- networking and hybrid infrastructure experience supports cloud architecture and IaC decisions;
- incident/change/service-management experience supports governance, response and operational design;
- project coordination and mentoring experience supports strategic leadership and knowledge sharing.

## Learning preference and workload model

The public IDR is structured around **on-the-job-aligned, evidence-based learning**. The initial cadence is approximately **3–4 focused hours per week** using short theory blocks followed by design, labs, documentation and mentor review.

The plan should be re-scoped rather than silently expanded if the workload becomes unsustainable.

## Capability proof rule

A capability is considered developed only when it can be traced to evidence such as:

- a current certification or official learning record;
- an architecture decision record;
- a reviewed reference architecture;
- a safe working lab;
- a tested script or IaC project;
- a risk/control artefact;
- a mentor review;
- an executive-ready brief or presentation.
