# References and Source Register

This register identifies the primary sources used to support the public IDR. Desh's professional baseline comes from the Skunkworks Academy development process and the sanitised capability profile already represented in this site. External sources below provide current technical, certification and standards context.

## Source hierarchy

Use sources in this order:

1. official vendor documentation and current certification study guides;
2. primary standards/framework owners;
3. official product security guidance;
4. supplementary community or training material only when needed.

For portfolio evidence, record the source URL and the date it was consulted.

## IDR interpretation rules

- Certification names, exam objectives and retirement dates can change. Re-check official vendor pages before booking.
- A listed credential is a learning milestone, not a promise that an exam remains available for the full 12-month roadmap.
- Vendor documentation describes product capability; Desh must still justify architecture decisions against context, risk, cost, operations and evidence.
- Frameworks such as NIST CSF, CIS Controls and MITRE ATT&CK are used as organising references, not as a substitute for an organisation-specific risk assessment.
- Public portfolio artefacts must use synthetic or expressly authorised data and must never expose employer/customer secrets, credentials, private logs or confidential architecture.

## Reference review cadence

The mentor should re-check the high-change references at **Day 30, Day 60, Day 90 and the annual review**, especially certification pages, product names and security-service documentation.
