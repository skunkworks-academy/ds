# Career Pathway

## Primary pathway

### Cloud & Cybersecurity Solution Architect / Senior Technical Lead

Build on substantial enterprise infrastructure and Microsoft-platform experience to own secure architecture, technical standards, modern-workplace security, cloud governance and cross-domain design decisions.

### Target capability profile

A strong outcome in this pathway means Desh can:

- design hybrid/cloud solutions across identity, endpoint, network, compute, storage, logging and resilience;
- make explicit architecture decisions and explain trade-offs;
- design Zero Trust access and endpoint controls;
- define SOC detection, triage and incident-response logic;
- automate repeatable infrastructure/security tasks safely;
- express infrastructure as code and validate it through CI;
- map technical risks to controls, evidence and business decisions;
- present architecture and security-modernisation plans to senior stakeholders.

## Secondary leadership pathway

### Infrastructure Manager / Cybersecurity Manager / IT Manager

Translate technical credibility into people leadership, investment decisions, risk ownership, vendor governance, delivery cadence and measurable operational improvement.

### Target leadership profile

- set priorities from risk and business value rather than tool preference;
- define measurable service/security outcomes;
- govern vendors, change, exceptions and recovery;
- mentor engineers and create repeatable standards;
- build staged roadmaps and budget assumptions;
- communicate technical uncertainty to executives;
- connect incidents, architecture debt and investment decisions.

## Role-decision criteria

At Day 90, compare the two pathways against evidence:

| Question | Architecture / Technical Lead signal | Manager / Security Manager signal |
|---|---|---|
| Best evidence | Deep architecture, automation and security designs | Governance, roadmap, people/stakeholder outcomes |
| Preferred work | Design decisions and technical standards | Portfolio/service ownership and prioritisation |
| Strongest feedback | Technical depth, system design, engineering quality | Communication, coordination, risk and leadership |
| Next gap | Broader design depth / specialist security | Budgeting, operating model, people/vendor governance |

The IDR can support both pathways during the first 90 days. After that, the mentor should weight projects and KPIs toward the pathway that best matches evidence and opportunity.

## Career evidence required

- architecture decision records;
- one secure hybrid-cloud reference architecture;
- one Zero Trust architecture;
- one SOC/detection engineering portfolio pack;
- automation code with tests and rollback notes;
- one Infrastructure-as-Code baseline;
- a risk and governance pack;
- an executive presentation connecting technology change to business outcomes;
- mentor feedback and a final capability review;
- four interview-ready stories tied to evidence.

## Conversion rule

Desh should not claim a capability because it appears in a course plan. The evidence must be inspectable, safe to disclose and defensible under questioning.
